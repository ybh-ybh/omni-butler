# 笔记功能 PRD

| 项目 | 内容 |
|---|---|
| 所属产品 | 知序 Omni Butler |
| 文档版本 | v1.1 |
| 文档状态 | 已纳入用户确认的产品决策，实施细节待评审，尚未进入开发 |
| 更新日期 | 2026-10-11 |
| 已确认语音方案 | 内置麦克风录音，转为可编辑文字，保留原音供回听 |
| 适用平台 | Windows、Android，沿用现有客户端范围 |
| 主要使用者 | 作者本人，兼顾同类个人记录需求 |
| 关联模块 | 首页、导航、功能管理、分类标签、全局搜索、回收站、数据同步 |

笔记用于随时记下想法、工作进展和生活感受。用户主动进入记录入口后立即得到一张空白笔记，以语音为主要输入方式，也可以直接打字；内容自动保存，类别与标签可以稍后补充，历史内容按时间、类别和标签查找。

首版的核心体验是：**打开就能记，记完就能走，之后找得到。** 日报和周报是笔记的使用场景，用户可以口述一篇完整报告，也可以先记录零散素材再自行整理。

## 1. 需求依据与产品边界

### 1.1 用户已明确的需求

| 编号 | 已明确需求 | 本文对应方案 |
|---|---|---|
| U-01 | 新增独立的“笔记”功能 | 独立记录入口、历史列表和笔记详情 |
| U-02 | 主动进入记录入口时新建空白笔记 | 切回应用、查看历史或返回正在录音的页面时保留原记录；纯空白页退出不留档 |
| U-03 | 内置语音输入，录音转为可编辑文字，并保留录音供回听 | 点击麦克风录音，结束后异步转写，支持编辑正文和原音回听；文字输入作为补充与兜底 |
| U-04 | 记录日常想法、日报、周报 | 支持短句、长文本、分段追加，不强制模板 |
| U-05 | 按物品管理的方式自定义管理类别，并支持多个标签 | 可新增、重命名、删除、调整类别；保存不要求先选类别或标签 |
| U-06 | 按时间、类别和用户标签整理 | 自动时间归档、自定义类别、多标签、组合筛选 |
| U-07 | 体验类似闪念胶囊 | 借鉴快速捕捉想法的定位，不预设硬件按键等具体能力 |
| U-08 | 切换应用或锁屏后继续录音 | 录音归属于原笔记，返回后恢复正在录音的页面与状态 |
| U-09 | 首版先做记录与手工整理 | AI 摘要、标签建议及自动生成日报周报后续加入 |
| U-10 | Android 提供独立底栏入口 | 新增“笔记”一级入口，Windows 使用独立侧栏入口 |
| U-11 | 单段最多 30 分钟、单篇累计最多 60 分钟 | 到限结束并保存，可按剩余额度追加或新建 |
| U-12 | 正文与原音随笔记一起删除 | 一起进入 30 天回收站、一起恢复，永久删除时一起清理 |

### 1.2 沿用约束与建议默认

第 1.1 节为用户已确认的产品决策。以下为沿用的项目约束及建议默认，未明确确认的细节不升级为用户需求。

- 沿用物品管理的单类别选择方式，一篇笔记可暂不选类别，也可以关联一个自定义类别，同时添加多个标签；类别与标签不设层级，不增加文件夹或笔记本。
- Android 保留现有五个入口，新增“笔记”为第六项；类别可暂不选，记录日期默认当天并允许补记。
- 延续本地优先、无注册登录、用户显式连接自托管同步服务的产品形态。
- 单段 30 分钟、单篇累计 60 分钟是已确认的产品上限，需要通过技术验证实现。其他数量与性能数值为建议验收基线，需在开发前冻结，不是已经达到的能力。

### 1.3 与既有碎片化内容规划的关系

总需求书第 8.2 节已经规划文本、语音、链接输入、原音同步、腾讯云 ASR、AI 整理及用户确认后的跨模块动作。笔记建议作为该方向的具体产品入口，复用同一份记录数据，避免未来再出现一套重复的“碎片箱”。

用户已确认首版先交付记录与人工整理，AI 摘要、标签建议和自动生成日报周报后续加入。原规划中的链接采集和跨模块建议仍列为后续规划。本模块的首版 AI 范围以本 PRD 的已确认决策为准；总需求书尚未同步本次分期，不能继续用其原有 AI P0 定义扩大笔记首版范围。

原规划要求删除碎片时可选择是否一并删除原音和整理结果。用户已确认笔记首版正文、原音和转写绑定删除：一起进入 30 天回收站、一起恢复，永久删除时一起清理，不提供删除整篇笔记后单独保留原音的选项。本模块以该确认规则为准；未来加入 AI 整理结果时另行定义其保留关系。

## 2. 背景与目标

### 2.1 要解决的问题

想法出现时，先选择分类、填写标题、打开复杂编辑器会增加记录负担；事后仅有一长串记录，又难以找出某天的想法或某个项目的周报素材。笔记把记录和整理分开：先低成本留下内容，再用稳定的日期和标签找回来。

### 2.2 产品目标与成功标准

| 目标 | 可验证标准 |
|---|---|
| 降低开始记录的成本 | 进入记录入口后，无须再点新建；已完成授权时一次点击即可开始录音 |
| 减少记录后的操作 | 不填写标题、不选类别、不加标签、不点击提交，也能保存有内容的笔记 |
| 支持工作与生活的长短记录 | 同一笔记可混合文字和多段语音；支持暂停、继续、追加 |
| 让内容容易回找 | 可按指定日期范围、类别、一个或多个标签、关键词组合查询 |
| 保证用户知道数据是否安全 | 本地保存、转写和跨端同步分别显示状态；失败不得伪装为成功 |
| 保留表达原意 | 用户编辑正文不改变原音；转写或后续 AI 处理不覆盖人工内容 |

### 2.3 首版范围

| 优先级 | 范围 | 交付要求 |
|---|---|---|
| P0 | 进入即写、文字编辑、自动保存、恢复 | 构成完整的本地记录闭环 |
| P0 | 内置录音、暂停继续、后台及锁屏录音、转写、回听、重试 | 录音结束后转为可编辑文字，保留原音供回听；验证单段 30 分钟与单篇累计 60 分钟 |
| P0 | 时间归档、自定义类别与标签、组合筛选、全文搜索 | 类别管理沿用物品管理方式，支持先记录后整理 |
| P0 | 编辑、删除、恢复、复制正文 | 接入现有 30 天回收站 |
| P0 | 功能开关、全局搜索、现有同步体系接入 | 关闭同步时仍能本地使用；启用同步后支持笔记与原音跨端 |
| P1 | 批量加减标签、批量导出 Markdown | 提高积累较多内容后的整理效率 |
| P1 | 日报、周报模板与选中素材汇编 | 用户主动触发，保留来源，不修改原笔记 |
| 后续 | AI 摘要、标签建议、日报周报生成、定时整理 | 独立评审隐私、成本、质量和确认机制 |
| 后续 | 链接解析、转待办、系统快捷入口、小组件 | 不构成本版发布门槛 |

首版不包含协作分享、公开发布、富文本排版、图片及普通文件附件、音频剪辑、说话人识别、离线识别模型、文件夹层级和完整日历视图。正文中可以粘贴链接，但不抓取网页或提取内容。

## 3. 用户场景

| 场景 | 用户行为 | 产品应提供的结果 |
|---|---|---|
| 突然想到一个点子 | 打开笔记，说二十秒，结束录音后离开 | 自动保存，允许不选类别、不加标签 |
| 每日工作记录 | 口述今天完成的事、遇到的问题与明天计划 | 一篇可继续编辑的笔记，可选自建“日报”类别，再加“工作”“项目 A”标签 |
| 每周工作总结 | 分几段口述一周情况，中途暂停后继续 | 各段归属于同一笔记，能回听并修正转写 |
| 锁屏或切应用后继续口述 | 开始录音后锁屏，或切到其他应用查看资料 | 录音继续写入原笔记，返回后可暂停或结束 |
| 周末整理素材 | 筛选本周与“项目 A”，逐条回顾 | 得到准确结果，可补标签或复制内容形成总结 |
| 补记昨天的想法 | 新建后把记录日期改为昨天 | 归入昨天，不伪造真实创建时间 |
| 离线记录 | 无网络时录音或输入文字 | 本地保存，录音待转写；联网后按授权状态处理 |
| 只想查看旧笔记 | 进入历史列表或点击搜索结果 | 打开已有记录，不覆盖它，也不产生新的持久记录 |

## 4. 信息架构与入口

### 4.1 页面组成

| 页面 | 核心内容 | 主要操作 |
|---|---|---|
| 记录页 | 空白正文、记录日期、录音按钮、保存状态 | 输入、录音、选择类别、添加标签、查看历史 |
| 历史列表 | 按日分组的笔记、时间范围、类别与标签筛选、搜索 | 打开笔记、新建、调整筛选 |
| 笔记详情 | 完整正文、语音片段、日期、类别、标签、状态 | 编辑、追加录音、复制、删除 |
| 类别管理 | 笔记专属类别及其使用情况 | 新建、重命名、改色、调整顺序、删除 |
| 标签管理 | 笔记专属标签及其使用数量 | 新建、重命名、调整顺序、删除 |
| 设置 | 模块开关、语音处理授权、服务状态 | 开关功能、查看能力、撤回后续处理授权 |
| 统一回收站 | 已删除笔记 | 恢复、永久删除 |

### 4.2 平台入口

- **Windows**：侧栏新增独立“笔记”入口，点击进入新记录页；页面中提供始终可见的“历史记录”入口。宽屏可并排展示列表和编辑区，初次进入编辑区仍为空白。
- **Android**：在现有五项底部导航之外新增独立“笔记”一级入口，建议顺序为首页、待办、时间、笔记、管理、设置；不把笔记放入“管理”聚合分区。点击“笔记”进入记录页，页内提供历史列表入口；历史中的“新建”直接开启空白记录。窄屏与大字号需保证六项导航可操作、选中状态和语义标签清楚。
- **设置**：在功能管理中新增“笔记”，建议沿用现有模块默认开启的规则；升级不能改动其他功能开关。关闭只隐藏业务入口，不删除记录，统一回收站仍可处理已删除内容。
- 从全局搜索、时间或标签筛选结果打开笔记时，直接打开该记录的详情。

### 4.3 记录页的交互层级

页面上方显示“笔记”、记录日期和“历史记录”；中央以空白正文为主，提示“想到什么，就说下来或写下来”；底部提供主操作“开始录音”、次操作“选择类别”和“添加标签”，并显示保存状态。类别与标签可以留空，不阻挡快速记录。

Windows 进入后正文可以直接输入；Android 进入后默认不弹软键盘，避免遮挡录音主操作，点击正文再呼出键盘。标题不是必填项，首版不单独设置标题编辑表单；列表展示标题从正文首个非空行截取，超过 30 个字显示省略号。无转写的纯音频记录显示“语音记录 · HH:mm”。

录音期间显示实际录音状态、已录时长、“暂停”和“结束”；暂停后显示“继续”和“结束”。不能只用颜色区分是否正在录音。页面不展示必须理解技术细节才能操作的字段。

## 5. 主要用户流程

### 5.1 快速记录

1. 点击笔记记录入口，立即出现新空白页。
2. 输入文字，或点击录音并在首次使用时完成麦克风授权。
3. 内容在本地自动保存；录音结束后保留音频，并按授权与服务状态启动转写。
4. 用户可修改文字、继续录音、选择类别或添加标签。录音结束后可以直接离开；尚在录音时切应用或锁屏，录音继续归属原笔记。
5. 没有进行中录音时，再次主动进入记录入口出现新的空白页；上一条在历史中可见。进行中录音的返回规则见第 6.1 节。

### 5.2 回顾与整理

1. 打开历史记录，默认显示全部日期、全部类别、全部标签的有效笔记。
2. 选择今天、本周、本月或自定义日期范围。
3. 选择类别与标签，必要时输入关键词缩小范围。
4. 打开笔记，修改正文、类别或标签，按需回听原音。
5. 返回列表后保持筛选条件和滚动位置。

### 5.3 日报与周报

用户可自行创建“日报”“周报”等类别，直接口述完整报告，结束后选择相应类别，再追加“工作”“项目 A”等主题标签。类别可自由管理，不固定为想法、日报、周报三种，也不强制预置这些类别；同一天可创建多篇日报，同一周可保存多份不同项目的周报。

回顾时用日期范围、类别和项目标签查找素材，复制所需正文。首版不自动合并多篇笔记，也不根据“日报”“周报”类别或标签生成总结。比如“本周 + 项目 A”检索的是记录日期落在本周的项目素材，不代表自动识别每篇文字描述的工作周期。

## 6. 新建与编辑规则

### 6.1 打开即新建的准确语义

| 触发事件 | 行为 |
|---|---|
| 从其他模块点击记录入口 | 提供新空白编辑器 |
| 在笔记内部点击“新建” | 先确保当前内容已在本地保存，再提供新空白编辑器 |
| 当前已经是空白编辑器，再次点击入口 | 保留该空白编辑器，不叠加空白页 |
| 记录页进入历史再返回 | 恢复原编辑器，不新建 |
| 点击历史记录、全局搜索结果 | 打开指定笔记，不新建 |
| 从其他模块重新进入笔记记录入口 | 提供新空白编辑器；此前内容留在历史中 |
| 切回应用、窗口重新聚焦、锁屏恢复 | 恢复当前状态，不新建；持续录音继续，已中断的录音不自动重开 |
| 页面预加载、主题切换、屏幕旋转、界面重建 | 不触发记录创建 |
| 应用重启后首次主动进入记录入口 | 显示新空白页，并对检测到的中断内容提供“恢复上次记录”提示 |

进行中录音优先保持原笔记上下文：切回应用、点击笔记导航入口或录音通知时返回正在录音的笔记，不新建。用户主动点击“新建”时，先结束并保存当前录音，再提供空白编辑器。同一设备同时只录制一段音频；历史浏览和其他页面编辑不能把当前录音改挂到别的笔记。

不得在页面构造、路由预加载或组件重建时创建正式笔记。现有 Android 导航会预加载页面，这一规则必须通过交互验证。

### 6.2 空白与有效内容

- 空白页是可输入状态，不等于立即新增数据库中的正式笔记。
- 首次出现非空白正文，或成功写入可播放的录音数据时，创建稳定的记录 ID 并开始持久化。
- 只有空格、换行、日期调整、类别或标签选择，没有正文和有效录音时，不进入历史、不计数、不同步；离开后丢弃这张空白页的元数据选择。
- 用户主动创建的类别与标签属于模块的管理库，即使最终未形成笔记也可以保留；允许在对应管理页删除未使用类别或标签。
- 录音未转写、转写失败或录音中没有识别到文字，均不能据此删除已有有效音频。
- 已经保存过的笔记被编辑为空时不静默删除，历史中显示“内容已清空”；只有显式删除才进入回收站。

### 6.3 自动保存

| 编号 | 需求 |
|---|---|
| SSN-SAVE-01 | 正文、记录日期、类别和标签修改后自动写入本地；文字停止输入 500 毫秒后触发保存，持续输入最长每 2 秒落盘一次 |
| SSN-SAVE-02 | 失焦、离开编辑器、打开另一条笔记及正常退出前，立即刷新待保存内容；保存成功不弹确认窗 |
| SSN-SAVE-03 | 显示“保存中”“已保存到本机”“保存失败，重试”；仅在本地持久化成功后显示已保存 |
| SSN-SAVE-04 | 保存失败时保留输入、提供重试与复制正文；主动离开时提示仍有未保存内容，不能静默丢弃 |
| SSN-SAVE-05 | 同一笔记的写入按版本处理，较早异步结果不得覆盖较新内容；快速连续新建不能产生重复记录 |
| SSN-SAVE-06 | 不依赖网络保存；同步失败和转写失败不得回滚已落盘正文 |

异常强退只能恢复已经持久化的内容，不能保证尚未落盘的最后输入。建议文字恢复窗口不超过 2 秒；录音恢复规则见第 7 节。系统禁止写入时不能继续显示“已保存”。

正文建议上限 20,000 字，超过时保留已输入内容并明确提示，禁止静默截断。超长粘贴应在写入前提示，保留剪贴板和原正文；转写结果超过正文容量时独立保留，允许查看和复制，不强行截断原始转写。

## 7. 语音记录与转写

首版采用已确认的内置语音方案：用户点击麦克风录音，录音转为可编辑文字，并保留原音供回听。默认不因打开页面而自动开启麦克风。

### 7.1 录音行为

| 编号 | 需求 |
|---|---|
| SSN-VOICE-01 | 点击“开始录音”后检查权限与设备状态，启动成功才显示正在录音；权限申请不在打开功能时强制弹出 |
| SSN-VOICE-02 | 支持开始、暂停、继续和结束；暂停不计入录音时长，继续仍属于同一段 |
| SSN-VOICE-03 | 一篇笔记可追加多段录音，按开始顺序排列；录音结束不自动开始下一篇笔记 |
| SSN-VOICE-04 | 单段最多 30 分钟、单篇累计最多 60 分钟；结束前 30 秒提示，达到单段上限或单篇剩余额度上限时自动结束并保存，可按剩余额度追加或新建 |
| SSN-VOICE-05 | 结束录音后可播放、暂停和拖动播放位置；播放时禁止并行录入同一设备扬声器声音，开始录音前停止播放 |
| SSN-VOICE-06 | 用户已启动的录音在离开记录页、切应用、窗口最小化及锁屏后继续；Android 提供持续录音通知及返回原笔记、暂停/继续、结束入口；Windows 返回窗口后显示相同录音状态 |
| SSN-VOICE-07 | 权限被拒绝、麦克风不可用或被其他应用占用时给出原因及重试/系统设置入口，文字输入继续可用 |
| SSN-VOICE-08 | 录音逐步写入私有目录并保存恢复检查点，不能只缓存在内存；建议异常中断最多损失最后 5 秒，实际必须真机验证 |
| SSN-VOICE-09 | 来电、麦克风被抢占、权限撤回、设备休眠或应用真正退出导致无法继续录音时，结束并保存可用部分；中断原因可见，恢复后不自动开启新录音 |

30/60 分钟上限和后台、锁屏继续录音是已确认的首版要求。技术设计需验证两端长录音、后台持续采集和中断恢复；不能以仅支持前台录音的方案替代验收。锁屏不同于设备休眠：正常锁屏继续录音，操作系统休眠等无法继续采集的状态按中断处理。

### 7.2 转写行为

- 原音先成功保存在本地，再进行网络上传和转写。用户已确认录音结束后异步生成文字，首版不提供边录边出字。
- 延续既有规划，优先验证后端统一调用腾讯云 ASR 的方案；不在客户端内置供应商长期密钥。服务商参数和最终技术方案在技术设计中确认。
- 首版验收以普通话为主，兼顾常见中英文混说；方言、强噪声和专业名词不作无条件准确承诺。
- 保存三份不同含义的数据：原始音频、原始转写结果、用户可编辑的笔记正文。手动修改正文不改写原始转写与原音。
- 录音开始时在笔记中预留对应语音片段位置。首次最终转写可填入该片段对应的文字位置；多段结果即使返回顺序不同，也按录音顺序呈现。
- 如果用户已经手动编辑或移除对应文字位置，迟到的转写只显示“转写已完成，待插入”，由用户选择插入位置；不替换当前正文。
- 重新转写产生新的候选结果，默认不再次追加、不覆盖正文；用户明确选择“使用这次结果”后才更新对应内容。
- 自动标点和自然分段可以开启；首版不擅自删掉否定词、改写语气、补充事实或概括成长摘要。

### 7.3 转写状态

| 状态 | 用户看到的内容 | 可执行操作 |
|---|---|---|
| 未启用 | 录音已保存，尚未启用语音转文字 | 回听、手动输入、查看启用说明 |
| 等待网络/服务 | 录音已保存，联网或服务恢复后可转写 | 回听、继续编辑、取消待处理任务 |
| 处理中 | 正在转写，对应音频仍可访问 | 继续编辑其他内容；不显示虚构完成百分比 |
| 成功 | 文字已生成，或待用户插入 | 校对、插入、回听 |
| 无有效识别结果 | 未识别到文字，录音仍保留 | 回听、重试、手动补充 |
| 失败 | 明确区分网络、配置、额度或服务异常 | 修复条件后重试；不要求重新录音 |
| 已取消 | 停止自动提交或应用该次结果 | 后续手动重试 |

短暂网络错误可有限重试，建议最多自动重试 3 次；权限、额度、配置等确定错误直接等待用户处理。超时或响应丢失后先查询原任务状态，不能以新任务身份反复收费。多设备查看同一录音时，不分别触发同一转写任务。

撤回授权后，不再提交未开始任务；已发送任务尝试取消，界面如实说明可能已经送达服务方。删除记录或切换数据源后，迟到结果不得恢复被删除笔记或写入新数据源。

## 8. 时间归档

### 8.1 时间字段的含义

| 字段 | 含义 | 是否可修改 | 用途 |
|---|---|---|---|
| 创建时间 | 首次产生有效内容并创建记录的真实时刻 | 否 | 显示创建顺序、同步审计 |
| 更新时间 | 最近一次正文、日期、类别或标签实际修改时刻 | 自动维护 | 编辑提示、冲突判断；只读和同步回执不改变它 |
| 记录日期 | 用户希望这篇笔记归属的自然日 | 是 | 时间分组与日期筛选 |
| 创建时区 | 首次记录时的设备时区及偏移信息 | 否 | 解释原始时间，避免跨端误读 |

记录日期默认取首次有效内容产生时的本地日期；若用户在空白页中主动选择过日期，则保留该选择。允许补记过去日期；首版不支持将记录日期设置到设备当前日期之后，未来计划可写在正文中。

例如 23:59 开始录音，00:03 结束，仍归到开始录音时的日期；23:59 只打开空白页，00:03 才首次输入，则默认归到新一天。跨时区查看时保持记录日期不变，创建/更新时间按当前设备时区展示，必要时可查看原始时区。

### 8.2 列表与筛选规则

- 默认全部日期，按记录日期倒序分组；同一天按创建时间倒序，时间相同按稳定 ID 确定顺序。
- 提供“今天”“本周”“本月”“自定义范围”“全部”。一周按周一至周日；自定义范围包含起止两天，开始日期不能晚于结束日期。
- “今天”等相对范围使用当前设备当地日期；列表跨日或应用恢复时刷新，当前正在编辑的笔记归属不自动改变。
- 修改记录日期后，笔记移动到相应日期组。修改正文或标签不把旧笔记顶到当天或列表顶部。
- 历史中的日期条件独立于第二期“日期管理”模块，不依赖其实现，不自动创建其他模块的日期标签。
- 本周、本月只是检索范围，不自动生成每日一篇、每周一篇的文档。

## 9. 类别与标签整理

### 9.1 类别与标签模型

用户已确认使用“自定义类别 + 多个标签”，类别的管理方式沿用物品管理。类别是可新增、调整和删除的管理项，不是固定的想法、日报、周报枚举。建议沿用现有单类别选择方式：一篇笔记可没有类别，或属于一个类别；不选类别时进入“未分类”集合，仍可正常保存。

类别与标签均属于笔记模块，同名项目不自动与物品、会员等模块共享。“日报”“周报”可由用户创建为类别；“工作”“生活”“学习”“项目 A”可作为标签示例。示例不强制预置，系统也不根据正文自动创建或选择类别、标签。

一篇笔记可有零个、一个或多个标签；标签只在笔记模块中管理，名称相同也不自动与物品、会员等模块的标签合并。建议每篇最多 10 个标签，每个名称 1 至 20 个字符；去除首尾空白，沿用现有同模块、同类型、不区分英文大小写的名称查重规则。

标签输入中的斜杠首版仅作为普通字符，不生成层级；类别同样不提供层级。

### 9.2 类别管理与归类

| 编号 | 需求 |
|---|---|
| SSN-CATEGORY-01 | 提供“管理类别”入口，复用物品管理所用的公共管理方式，支持新增、重命名、改色、调整顺序和删除 |
| SSN-CATEGORY-02 | 记录时或记录后均可选择、替换或清除类别，修改后自动保存；选择类别不是首次保存的前置条件 |
| SSN-CATEGORY-03 | 新增和重命名沿用公共名称校验，同模块同类型名称去首尾空白并忽略英文大小写查重；重复名称提示冲突，不自动合并 |
| SSN-CATEGORY-04 | 重命名有效类别后，所有关联笔记展示新名称；不替换正文中出现的同名文字 |
| SSN-CATEGORY-05 | 删除类别沿用物品管理的保留历史名称语义：新记录不能再选择该类别，已有笔记保留带“已删除”标记的历史类别名称；正文、标签和原音不受影响 |
| SSN-CATEGORY-06 | 没有有效类别的笔记可从“未分类”找到，包括原类别已删除的笔记；用户可重新归类，删除前明确提示影响，并沿用公共撤销操作 |

类别删除与标签删除采用不同的既定展示语义：历史类别名称仅用于回顾，不再作为有效分类选择；标签删除按第 9.3 节解除关联。实现时需保存必要的历史类别显示信息，不能因为公共查询过滤已删除类别而让历史名称消失。

### 9.3 标签新增与调整

| 编号 | 需求 |
|---|---|
| SSN-TAG-01 | 记录时及记录后均可打开标签选择器，搜索已有标签或明确选择“创建新标签” |
| SSN-TAG-02 | 标签不是保存前置条件，不强制进入分类页面 |
| SSN-TAG-03 | 支持增加、移除关联，修改后自动保存；移除单篇关联不删除标签本身 |
| SSN-TAG-04 | 支持重命名，名称变化作用于所有关联笔记；遇到同名只提示冲突，首版不自动合并 |
| SSN-TAG-05 | 支持标签颜色及顺序，优先复用现有公共管理控件；颜色不作为唯一识别方式 |
| SSN-TAG-06 | 删除标签前显示受影响笔记数，确认后解除关联，保留全部正文和音频；标签名不从正文中做字符串删除 |
| SSN-TAG-07 | 删除后的标签不再筛选和计数，笔记失去最后一个标签后进入“未打标签”；回收站笔记恢复时只恢复仍有效的标签 |

当前其他模块的标签删除提示有“保留历史名称”的语义，本模块采用“移除标签关联、保留笔记”的明确规则。需要在公共能力中提供模块差异，不能顺手改动其他模块的行为。

### 9.4 分类与筛选逻辑

- 类别筛选提供“全部类别”“未分类”以及当前有效的自定义类别，单次选择一个类别条件；记录中没有有效类别时匹配“未分类”。
- “未打标签”是没有有效标签的自动集合，不是用户必须完成的整理任务；它也不判断用户是否已经读过或整理过。
- 选择多个标签时采用**交集**：同时拥有全部所选标签才匹配。界面显示“同时包含这些标签”。首版不增加交集/并集切换。
- “未打标签”与具体标签筛选互斥；选择其中一项时清除另一类选择并即时显示结果。
- 日期、类别、标签、关键词之间同样取交集；未选择某项代表该项不限制。“未分类”可以与任意标签条件组合，与“未打标签”是两种独立状态。
- 搜索首版按一个完整关键词匹配展示标题或笔记正文，忽略英文大小写，中文采用连续文本匹配；搜索已确认的正文，不将未插入的候选转写当作正文结果。
- 纯音频笔记仍能通过日期和标签找到；未转写或未插入正文的语音内容不承诺关键词命中。标签名称通过标签选择器搜索。
- 返回列表保留当前筛选；重新进入历史时可保留当前应用会话内条件，并始终显示筛选项及“一键清除”，不跨设备同步筛选状态。

## 10. 历史列表与笔记操作

每条列表项显示摘要标题、正文前两行、记录日期/创建时刻、类别、标签，以及必要的音频时长和异常状态。普通状态保持简洁，转写失败、保存失败或同步异常必须可发现。列表按需加载，不一次渲染全部正文和音频。

支持以下操作：

- 打开详情并继续编辑正文、调整日期、类别与标签，或追加录音。
- 复制正文；复制结果包含当前可见完整正文，不包含内部 ID、同步日志或未采用的转写结果。
- 删除整篇笔记，进入统一回收站，并提供与现有产品一致的短时撤销。
- 从回收站恢复正文、类别及必要的历史名称、有效标签和仍保留的音频；恢复后回到原记录日期。已删除类别仍只能作为历史名称，不因恢复笔记而复活。
- P1 批量加减标签和导出由用户显式选择记录后操作；不得把“追加标签”实现为覆盖原有全部标签。

首版不单独提供删除某段原音的入口，避免出现正文还依赖音频却已失去原音的含糊状态；用户删除正文中的转写文字时，音频仍可在该笔记的录音区找到。永久删除整篇笔记时同步清理关联原音与转写。

## 11. 本地保存、同步与删除

### 11.1 本地与云端能力

| 能力 | 未连接服务器 | 已连接，但语音服务未启用 | 同步与语音服务均可用 |
|---|---|---|---|
| 文字记录、日期、类别、标签、搜索、回收站 | 本地可用 | 本地可用并参与结构化同步 | 本地可用并参与结构化同步 |
| 录音与本机回听 | 可用 | 可用 | 可用 |
| 原音跨端 | 不可用 | 取决于服务器音频存储能力 | 上传完成后可用 |
| 自动转写 | 不可用，保留原音 | 不可用，提示未配置/未授权 | 授权后异步处理 |

开启数据同步不等于同意第三方语音处理；首次连接服务器不自动转写全部历史录音。用户启用语音处理时分别确认“以后新录音自动转写”和“是否处理现有待转写录音”。关闭本机同步后停止该设备的上传、新任务提交和结果接收；服务端已经接收的任务可能继续执行，重新连接原数据源后查询原任务状态，不重新提交同一任务。

本机断开同步与撤回云端处理授权是两个动作：前者不影响其他仍连接的设备，后者需要提交到当前自托管服务才能阻止服务端尚未开始的处理。离线时撤回只立即阻止本机提交，并显示“服务端撤回待送达”，不能宣称服务端授权已经撤销。

笔记同步状态、音频传输状态、转写状态分别表达。例如：“文字已同步，1 段录音待上传”；不能仅用一个“已同步”掩盖附件缺失。另一设备没有音频缓存且离线时显示“录音尚未下载”，已有正文仍可读写。

服务器新增原音和迁移暂存音频统一保存到 MinIO 独立私有桶 `omni-butler-note-audio`，复用既有实例和持久凭证；图片仍使用原桶。MinIO 常驻，不受图片同步开关影响。客户端继续保留本机录音及缓存以支持离线；下载经过后端鉴权，腾讯长音频使用任务签名 API 链接，不开放 MinIO 公网端口或匿名访问。对象存储失败保留上传重试与删除回执，不回退写入服务器磁盘。服务器完整备份必须同时覆盖 PostgreSQL、MinIO 数据卷及凭证卷。

### 11.2 并发与恢复

- 记录和每个录音片段都有稳定身份；重试、断网重连和应用重启不创建重复内容。
- 用户编辑旧版本时如发现远端更新，必须保留双方内容并提示选择版本；正文不采用无提示的最后写入覆盖。冲突处理的本机候选在解决前可恢复，不能只是内存状态；用户永久删除所属笔记时按第 11.3 节一并清理。
- 标签按实际新增/移除关联同步，不用打开详情时的旧标签快照覆盖其他设备的新关联。并发相反操作无法自动判断时提示冲突。
- 类别及笔记的归类关系参与同步；两端同时改为不同类别时保留候选并提示处理，不把单类别自动变成多个类别，也不借旧详情快照回写其他未修改字段。
- 一端删除、另一端离线编辑时，原记录保持删除状态；未提交内容保存为可恢复候选，需用户明确选择“另存新笔记”才出现在活动列表。
- 恢复或重新运行转写前检查笔记及片段是否有效、数据源身份是否一致；已删除记录不因后台任务自动复活。
- 服务器迁移、全量快照和备份必须覆盖笔记、类别、标签及关联关系、历史类别显示信息、音频元数据、可恢复正文候选与相关待处理状态。完整迁移或完整备份还必须包含全部引用音频的文件本体，并按摘要验证完整性；已另存笔记引用的音频也在其范围内。
- 尚未下载的远端音频应先尝试获取。无法获取时，在迁移确认前明确列出缺失清单，由用户选择先补齐或继续不完整迁移；保留旧数据源的恢复资料，完成页持续标明“结构化数据已迁移，音频不完整”。不完整备份不得标为完整备份，新服务器需验证已迁移音频可回听。
- 在途转写任务保持与原数据源绑定，恢复到另一服务器时不能携带旧任务身份继续提交或应用其迟到结果；需要重新转写的片段先明确提示，并由用户确认后在新数据源创建新任务。
- 兼容性不匹配时停止新模块同步并保留本地数据；升级方案不得要求清空现有业务库。

### 11.3 回收站与附件生命周期

整篇删除沿用现有 30 天回收站规则。保留期内正文、原始转写和原音一并保留，普通列表、搜索和计数排除已删除笔记。语音任务停止进一步提交；已经发送的任务仍需防止结果重新写入活动记录。

用户确认永久删除或记录超过回收站保留期后，逻辑上删除正文、转写、类别与标签关联及音频引用，清理本机文件，并向服务器提交删除；不删除供其他笔记使用的类别或标签管理项。云端不可达时显示删除待同步；联网后服务端清理对象文件，其他设备在收到删除后清理本机缓存。不能承诺离线设备或外部备份即时抹除。

永久删除的确认说明必须包含该笔记下全部未处理恢复/冲突候选；超过保留期自动清理也执行相同范围，候选不能成为永久保留已删除内容的入口。此前已由用户成功“另存新笔记”的内容属于独立记录，其音频在完成独立引用或复制后保留，不随原笔记删除；底层共享文件只有在没有有效引用时才清理。

服务端附件清理失败应有可重试状态，不能留下仍可访问的公开地址。原音默认保留到对应笔记永久删除；隐私说明区分业务服务中的删除与用户自行保存的备份、服务商保留策略。

## 12. 页面状态与异常处理

| 状态或异常 | 产品行为 |
|---|---|
| 第一次使用，没有历史 | 记录页直接可用；历史页提示“还没有笔记”并提供“记一条” |
| 筛选无结果 | 展示当前条件，提供清除筛选；不暗示数据已丢失 |
| 本地读取失败 | 显示重试，保留当前未保存输入，禁止用空列表覆盖真实数据 |
| 本地保存失败或空间不足 | 持续提示，保留正文并可复制；录音停止增长并尽量保存已经写入的部分 |
| 意外退出后存在恢复内容 | 正常入口仍可新记；展示“发现上次中断的记录”，允许恢复或明确丢弃 |
| 麦克风权限拒绝/撤回 | 结束录音、保存可用部分，提示授权方式，文字输入仍可用 |
| 切换应用、页面或正常锁屏 | 已启动的录音继续写入原笔记；Android 持续通知可返回、暂停或结束，回到应用恢复原状态 |
| 来电、设备休眠、采集设备被抢占或应用真正退出 | 无法持续采集时结束并保存，说明原因；恢复后不自动开始新录音 |
| 网络中断 | 本地记录继续；传输与转写分别显示待重试 |
| 音频损坏或文件缺失 | 标注具体片段，能从服务端重新获取时提供重试；不删除正文 |
| 转写返回晚于用户编辑 | 保留人工正文，转写作为待插入候选 |
| 服务未配置或额度不足 | 显示明确原因，不无限重试，保留录音 |
| 关闭笔记模块 | 若正在录音先结束并保存，隐藏入口；数据和既有同步设置不被清除 |
| 服务器迁移期间 | 遵守现有维护门禁；先结束录音、刷新正文、暂停传输，完成后再恢复任务 |

## 13. 数据与能力边界

下表定义产品语义，不固定最终物理表名、接口路径或数据库版本号。详细结构由技术设计结合现有同步协议确定。

| 实体 | 必需信息 | 主要规则 |
|---|---|---|
| 笔记 | 稳定 ID、正文、记录日期、创建/更新时间、创建时区、版本、删除时间、数据归属 | 可独立于音频存在；正文与候选转写分离 |
| 录音片段 | 片段 ID、笔记 ID、顺序、时长、格式、校验摘要、有效状态 | 一篇多段；本机路径与服务端对象身份分离 |
| 原始转写 | 片段 ID、结果版本、文本、生成时间、采用状态 | 重试结果可比较，不自动覆盖人工正文 |
| 转写任务 | 稳定任务 ID、片段/音频版本、状态、失败原因、尝试次数 | 同一请求幂等；服务端统一调度 |
| 类别及归类 | 类别 ID、模块、名称、颜色、排序、删除状态、笔记归类与历史显示信息 | 建议一篇零或一个类别；类别自定义管理，删除后保留历史名称、不删笔记 |
| 标签及关联 | 标签 ID、模块、名称、颜色、排序、笔记与标签关系 | 一篇多标签，按 ID 关联，重命名不改正文 |
| 恢复与冲突候选 | 对应记录及版本、候选正文/音频恢复信息、原因 | 用户确认处理前保持可恢复，不能冒充正式新笔记 |
| 设备偏好 | 功能开关、会话内筛选状态、麦克风与界面偏好 | 按现有本机偏好规则处理，不伪装成跨端业务数据 |
| 处理授权 | 授权范围、版本、状态、确认时间、服务端确认状态 | 本机立即停止未授权提交；服务端收到撤回后阻止未开始任务，离线撤回明确显示待送达 |

必须接入或扩展的现有能力包括：功能枚举与一级导航、模块级类别与标签、全局搜索、回收站白名单、Drift/Prisma 结构、同步表与字段白名单、PowerSync 下行、迁移快照与备份。Android 新增一级分支时需核对保活、预加载及一级横滑行为，不能因增加底栏项触发空白笔记持久化。当前图片接口只支持物品和会员主图，不能直接用图片接口接收音频。

音频附件、录音权限及录制能力、后台持续录音、ASR 调度均属于新增能力。可复用现有认证、私有存储和重试模式，但需要各自验证，不能把“已有图片同步”当作“已有语音同步”。

## 14. 隐私、可用性与性能

### 14.1 隐私与权限

- 麦克风由用户操作触发，不在页面打开、进入后台或定时任务中自动开始录音；用户已主动启动的录音可在后台和锁屏时继续，并提供持续录音状态及停止入口。
- 首次启用云端转写时，说明发送的是所选录音、接收方为自托管服务及语音供应商、处理用途与保留方式；拒绝后仍可录音和写字。
- 用于转写的服务不需要收到无关笔记正文、类别、标签或其他模块数据；后续 AI 整理另行确认数据范围。
- 原音与正文默认私有；跨端访问必须校验当前数据归属和设备会话，不生成永久公开音频链接。
- 日志与统计不记录音频内容、完整正文、转写全文、类别或标签名称、敏感凭据。
- 本地私有目录不等于数据库和音频已经加密，不在产品文案中宣称端到端加密。

### 14.2 可用性

复用现有 Omni 组件、配色、深浅主题与响应式规则。Android 主要操作的触控热区至少 48 逻辑像素，六项底栏在窄屏和大字号下仍可使用，录音按钮与输入法、安全区互不遮挡；大字号时日期、类别、标签和操作可以换行。

Windows 可使用键盘完成文字记录、标签选择、搜索和返回；语音按钮有明确的可访问名称。读屏能够区分录音、暂停、保存失败与转写完成；不逐秒播报时长打断用户。减少动画设置不影响状态判断。

### 14.3 性能与可靠性验收基线

| 项目 | 建议门槛 | 测量条件 |
|---|---|---|
| 新记录页可交互 | P95 不超过 1 秒 | 已启动应用，从点击记录入口到可输入；另行记录应用冷启动耗时 |
| 录音启动反馈 | P95 不超过 1 秒 | 已授权且麦克风可用，点击后直到真实采集开始 |
| 本地历史首屏 | P95 不超过 2 秒 | 10,000 条笔记、平均正文 500 字，附件不全量加载 |
| 日期/标签/关键词查询 | P95 不超过 1 秒 | 同一数据集，不依赖网络 |
| 转写可用性 | 在发布前用真实服务样本验证并冻结耗时门槛 | 普通话短句、1 分钟及 30 分钟录音分别统计，另验证单篇累计 60 分钟多段结果，不假定固定时延 |
| 录音可恢复性 | 已落盘片段全部可恢复，目标损失不超过最后 5 秒；正常后台及锁屏不应中断 | 强退、来电、休眠、磁盘异常及 30 分钟后台/锁屏持续录音分别验证 |
| 保存与冲突 | 验收中不得出现已提示保存成功的内容丢失或静默覆盖 | 覆盖重启、双端离线修改、删除与迟到转写 |

Windows 和 Android 分别记录设备、系统、构建模式、数据量与网络条件；性能使用发布构建测量。转写质量用固定中文样本核对否定词、数字、专名和长段落，不以“请求成功”替代内容质量验收。

## 15. 观察指标

首版为个人使用工具，不为本功能额外引入外部统计平台。允许用本机诊断或受控测试记录以下指标，内容相关数据不得进入日志；跨端汇总前按稳定记录 ID 去重。

| 指标 | 定义 | 用途 |
|---|---|---|
| 开始记录耗时 | 点击记录入口到首次有效文字或实际录音开始的时长 | 判断入口是否顺手 |
| 记录保存成功率 | 成功持久化次数 / 实际发起保存次数 | 发现保存可靠性问题 |
| 转写完成率 | 成功产生最终文本的唯一任务数 / 已提交且结束的唯一任务数 | 区分空识别、失败和取消，不用重试次数扩大分母 |
| 无标签占比 | 没有有效标签的活动笔记数 / 活动笔记总数 | 观察整理习惯，不把未打标签视为失败 |
| 回顾使用情况 | 从历史、日期、标签或搜索打开旧笔记的次数 | 判断内容是否能够被再次利用 |
| 恢复与同步异常数 | 未完成恢复、冲突、附件传输失败的数量 | 优先处理数据可靠性风险 |

使用频率、留存和标签使用率不预设无依据的增长目标；内部试用形成基线后再设改进目标。

| AC-31 | 自定义类别的新增、选择、清除、重命名、改色、排序、删除和撤销 | 类别不限于想法/日报/周报；未分类可保存；删除类别不删笔记，历史名称保留并可重新归类 |
| AC-32 | 来电、权限撤回、采集设备被抢占、休眠或真正退出 | 按中断规则保留可播放部分，原因可见，恢复后不自动开始新录音 |
| AC-33 | 后台录音时返回笔记入口、浏览其他笔记、主动新建 | 返回原录音不新建；浏览不改变录音归属；主动新建先结束保存当前录音，避免并行录音或串到新笔记 |

## 17. 分期与发布条件

| 阶段 | 交付物 | 完成条件 |
|---|---|---|
| 需求评审 | 纳入已确认决策的本 PRD、关键交互和建议默认 | 功能名称、首版 AI 分期、类别方式、入口、后台录音、30/60 分钟上限与绑定删除已确定，评审实施细节 |
| 可行性验证 | 两端录音恢复样例、真实转写样本、附件与并发方案 | 验证 30 分钟连续录音、60 分钟多段记录、后台/锁屏录音、任务幂等、服务费用及数据恢复；形成技术设计 |
| 本地闭环 | 新建、编辑、自动保存、类别与标签、时间、搜索、回收站 | 本地相关 P0 验收通过，可内部试用 |
| 语音与同步闭环 | 录音转写、原音跨端、冲突和迁移处理 | 两端及真实服务链路相关 P0 验收通过 |
| 首版发布 | 升级说明、能力配置说明、完整验收记录 | 全部 P0 通过，无已知数据丢失、误覆盖或越权访问问题 |
| 后续增强 | 批量整理、导出、模板、智能整理 | 根据实际使用反馈独立评审，不回写原始内容 |

开发排期需在语音和同步技术验证后估算，不在缺少工作量证据时承诺交付天数。上线涉及服务端结构时，先完成数据库、API、存储及同步规则升级，再发布依赖这些能力的客户端；不兼容服务可降级为本地记录并提示能力受限。

本任务已进入功能实现与本机验证阶段。用户于 2026-10-11 确认暂不能提供 Android 测试手机及公网 HTTPS 地址，先完成本机代码和可执行验证；真机后台/锁屏与公网长音频验收暂缓，首版发布条件仍按本节执行。未部署正式服务。本机授权测试笔记已在两个客户端正常退出后备份清理；重开真实运行时验证笔记表、待上传操作及恢复清单均为空，其他模块数据、设置与历史备份保留。

## 18. 已确认决策与实施验证

| 事项 | 已确认方案 | 实施要求 |
|---|---|---|
| 功能名称 | 笔记 | 文档标题、功能入口、页面文案统一使用“笔记” |
| 新建时机 | 主动进入记录入口才新建，空白页不留档 | 切回应用、历史浏览和返回正在录音的页面保持原记录 |
| 语音方式与转写时机 | 内置录音、结束后转为可编辑文字、保留原音 | 首版不提供实时出字，原音和人工正文独立保存 |
| 首版 AI 分期 | 先记录与手工整理，AI 后续加入 | 不把旧总需求书的 AI P0 自动纳入笔记首版；后续同步需求文档 |
| 类别与标签 | 按物品管理方式自定义管理类别，同时支持多个标签 | 提供类别管理入口，不固定为想法/日报/周报，不以标签替代类别 |
| Android 入口 | 独立底栏入口 | 按第六项入口方案验证导航、保活、窄屏和大字号；Windows 保留独立侧栏方案 |
| 后台与锁屏 | 已启动录音继续 | 两端验证持续采集和停止入口，无法采集的中断按第 7.1 节保存 |
| 录音长度 | 单段最多 30 分钟，单篇累计最多 60 分钟 | 验证长录音、剩余额度、转写耗时和服务成本，不自行降为旧 10/30 分钟上限 |
| 删除关系 | 正文、原音和转写随笔记一起删除与恢复 | 30 天回收站完整保留，永久删除一起清理，不提供独立保留原音选项 |
| 服务器音频存储 | MinIO 私有桶，客户端保留本地录音和缓存 | 新增原音和迁移暂存统一写入 `omni-butler-note-audio`；常驻实例与图片共用，图片开关不影响音频；失败不回退磁盘 |
| 本机测试笔记 | 备份后通过一次性维护工具清理 | 正常退出两个客户端后，清理活动库全部笔记、恢复清单和笔记待上传操作，保留类别、标签、其他模块数据与事务身份；服务器尚无笔记数据，不迁移历史原音 |
| 当前验收范围 | 先完成本机代码和可执行验证 | 用户暂不能提供 Android 测试手机及公网 HTTPS 地址；真机后台/锁屏、实际长录音和公网长音频验收延期，完整发布条件保持不变 |

沿用既有腾讯云 ASR 规划，音频存储已确认采用 MinIO。本次仅完成代码、部署配置和本机验证，不部署正式服务器，不新增付费识别。后台录音和中断恢复能力、同步冲突及迁移完整性仍按相应验收标准验证。建议默认与未逐项确认的细节保留在第 1.2 节及相应需求段落中，不表示用户已批准所有技术方案。

主要风险是语音服务不可用时的体验、长录音意外中断、跨端编辑覆盖，以及新模块未完整接入同步/迁移/回收站。首版应优先通过这些场景的真实验证；不能只凭正常联网情况下“录音能转文字”即判断功能完成。
