# 进度任务

待办编辑器可创建普通任务或进度任务。进度任务使用独立步骤，支持空名称、跳序完成和批量记录；不会展开为普通子任务树。

## 使用规则

- 创建输入1～1000步，单位可选（默认显示“步”），名称可全部留空。保存后任务类型固定，通过添加、删除指定步骤和上下移动调整结构。
- 进度编辑器桌面将数量、更新步骤和单位并排，编辑已有任务只读展示总数。步骤名称与操作同行，窄屏使用更多菜单；五项以内完整展示，长列表按可用高度滚动。添加后自动展开并定位、聚焦新项；单位和名称只在接近长度上限时显示框内计数，原有长度限制、删除确认与完成只读规则不变。
- 步骤等权重，分子是已完成步骤数。24步以内且每段至少8逻辑像素时按实际位置点亮，否则显示连续比例条。
- 进度条节点悬停不弹出提示；步骤名称和状态通过进度面板查看。
- 首页、待办任务正文和悬浮窗打开同一个即时保存面板；首页与待办的“+1”按钮直接完成按用户顺序排列的首个未完成步骤，提示为“完成下一个”，提交中禁用重复操作，成功后可撤销。最后一步完成后仍需确认任务完成；列表不支持拖动进度条。批量操作先预览具体步骤，再写入稳定ID的目标状态。
- 进度面板顶部将下一个步骤与完成按钮同排，批量数量使用外置标签和短输入框；大字号或空间不足时自动分行。长名称可悬停或长按查看，数量错误另占整行，批量预览及确认继续按原流程显示。
- 每日待办中普通任务单击仅展开/收起子项；进度任务正文单击打开进度面板。Windows右键或Android长按任务项打开编辑/移动象限/回收站菜单，子任务没有移动入口；不再显示更多按钮，键盘可使用菜单键或Shift+F10。完成下一个图标与添加子任务保持相同尺寸。
- 全满仅表示“待确认完成”。确认才进入历史并取消任务提醒；重新打开保留步骤状态。步骤不独立计入未完成数、不提供提醒。
- 进度任务只能作为独立根任务，一期不重复、不挂子任务、不提供加权或每日增量统计。

## Windows 完成历史

- Windows默认直接显示进行中看板，不展示进行中按钮；完成历史入口位于页头右侧、新增待办旁。历史页提供“退出”返回原看板，窄窗及大字号仍保留入口。
- 概览展示含今天的最近7、30、365个本地自然日完成数，以及最近365天的逐日热力图；章节每完成一步计1项，进度任务的整体确认不额外计数。普通子任务各计1项，有有效子任务的父任务不计数。
- 热力图直接居中显示在页面背景上，不使用顶部卡片。常规字号日期格16dp、间距6dp，随放大字号增大；左侧固定显示周一、周四、周日并对齐对应日期行，窄窗只横向滚动日期网格。底部日期范围和图例保持隐藏，空格点击无操作；有记录日期沿用笔记页的缩放、主题光晕和提示，再次点击已选日期取消日期筛选。
- 周/月/年统计固定在下方左栏卡片顶部，沿用笔记侧栏的数字在上、标签在下和左中右三列对齐；仅显示“周／月／年”，悬停显示最近一周、最近一个月、最近一年。窄窗收起左栏时统计移入下方结果卡片，归档和列表筛选始终不改变统计口径。
- 左栏任务类型仅“普通任务／进度任务”，子任务归入普通任务；再次选择当前类型可取消类型筛选，清除筛选恢复全部记录。类型、“全部时间”和月份条目与AI助手侧栏任务项同为最小34dp，大字号按内容增高。右侧默认保留全部年份历史，同日同所属任务默认合并收起，关键词同时检索任务、描述、父任务及章节名称，并自动展开匹配明细。
- 历史搜索栏采用笔记页同款灰底、圆角、悬停细边框和聚焦表面，右端仅保留数量与筛选图标。开始日期、结束日期和“清空筛选”统一收进锚定菜单，日期选择仍即时生效，支持单侧及同日范围；清空同时撤销关键词、类型和日期。窄窗类型/月归档入口也在该面板内，不再将工具排到搜索栏外；Escape关闭菜单保留已选条件。
- 右侧匹配完成单元数量常驻搜索框内部右侧，显示“N 项”，筛选后同步变化，零结果显示0项；不再独占标题行。日期使用12dp主题次要文字，保留当天数量；任务间不画横线，首个日期顶部12dp、后续日期16dp、日期下方及同日组间4dp，通过留白区分层级，展开明细仍逐行惰性构建。
- 热力图、月份和起止日期共用一个日期范围，关键词、类型与日期取交集；列表筛选不改变概览或归档数量。取消完成、删除后相应记录扣除，重新完成归入新的日期，恢复删除沿用原时间。
- 普通历史项可单独编辑或重新打开，章节继续通过原进度面板修改；组头不提供可能影响其他日期的整体撤销。Android保留原有按日历史。
- Windows周/月/年提示分别使用`OmniWindowsSemanticsBoundary`保留独立语义锚点，避免相邻提示合并导致原生AXTree更新失败。回归需开启语义并实际悬停、退出历史；原生探针为`tool/notes_windows_accessibility_probe.dart --todo-history-statistics`，可加`--narrow --dark`，仅使用内存数据。构建探针后须恢复`--target lib/main.dart`；不要覆盖或终止正在运行的客户端。

## 数据与冲突

`todo_items.task_type`默认`normal`，进度类型为`progress`；`progress_unit`可空。`todo_progress_steps`保存稳定ID、归属、名称、顺序和逐项状态，数量由有效步骤计算。

服务端只取消已失效的完成确认，不根据全满自动完成。晚到的离线确认若遇到未完成步骤，正常确认上传事务并下发未完成状态。并发归零保留任务并要求补步骤；并发超过1000步保留全部数据、允许编辑已有步骤，禁止继续追加。

结构编辑以打开时的ID、名称和顺序为基线，不包含完成状态。仅改元数据不写回步骤；结构保存遇到基线变化时保留输入并报错，避免删除同步期间新增项或覆盖其他设备改名。逐项撤销比较本次状态与毫秒精度的版本时间，后续变更不被撤销覆盖。

父任务软删除仅隐藏其步骤，不改写步骤自己的删除状态，避免混淆单独删除与整任务删除。恢复父项不会复活单独删除步骤；永久清理父项同时清理步骤并保留同步墓碑。

## 升级

- 使用增量迁移升级本地数据库和PostgreSQL，同时更新PowerSync publication、表定义与下行查询。
- 同步schema版本为2，现有同步接口携带`X-Omni-Sync-Schema: 2`，预检、会话和token响应包含`syncSchemaVersion`。不兼容时保留数据库、会话与队列，停止同步并提示升级。
- 新快照写v2；读取本地旧v1时补普通任务类型和空步骤表。已提交旧换服操作仍按原migrationId查询回执，不二次覆盖服务器。
- 先部署服务器及同步配置，再更新全部客户端。旧客户端已有短期凭证可能短暂继续读，但不能上传或覆盖新数据。

## 验证入口

- `todo_progress_repository_test.dart`：跳序、确认/重开、撤销、结构冲突、删除恢复与旧快照。
- `todo_progress_ui_test.dart`、`todo_progress_entrypoints_test.dart`：编辑、即时记录、批量、入口一致和窄屏。
- `todo_progress_quick_action_test.dart`：快捷加一的提交防重、卸载后继续写入、失败重试、精确撤销和读取未就绪禁用。
- `todo_progress_panel_layout_test.dart`：顶部紧凑布局、加一精确目标、窄屏大字号与批量校验；设置 `OMNI_PROGRESS_PANEL_PREVIEW=1` 可输出中文预览。
- `powersync_server_e2e_test.dart`：真实双设备离线合并及过期确认纠正。
- `powersync_migration_e2e_test.dart`：真实首次合并、换服、覆盖及采用服务器流程。
- `test/support/todo_progress_runtime_smoke.dart`：隔离内存数据的 Windows / Android 真实引擎点击验证，不访问正式数据库或同步会话。
- 服务端`sync.integration.spec.ts`：真实迁移、所有者边界、墓碑、快照与事务收敛。

可设置`OMNI_PROGRESS_PREVIEW`为输出目录，运行入口测试生成带中文字体的界面预览。生成预览使用内存数据库与隔离偏好，不访问正式业务数据。

真实运行时验证可执行 `flutter run -d windows -t test/support/todo_progress_runtime_smoke.dart`，或将设备替换为已启动的 Android 模拟器。以日志中的 `PASS: todo_progress_runtime_smoke` 判断业务与渲染验证通过；Windows 可用 `OMNI_PROGRESS_RUNTIME_CAPTURE` 指定绝对目录，保存关键状态截图。

## 本轮验证结果（2026-10-07）

- 客户端全量测试：540通过、5项环境依赖测试跳过、1项既有截图基线差异。进度任务仓储、迁移、同步门禁、回收站、11项专用UI测试及3项入口测试均通过。
- 真实PowerSync双设备3项、换服迁移1项另行启用并通过，覆盖离线跳序合并、重试、过期确认纠正与队列清空。
- 服务端64项单元/HTTP测试、42项真实PostgreSQL集成测试通过；Prisma生成、Nest构建与限定ESLint通过。
- Flutter全量静态检查、UI样式检查、Windows正式入口Debug构建、Android正式入口Debug APK构建通过。
- Windows原生窗口和Android模拟器通过真实Flutter引擎指针命中验证：第1/3/8步、下一步、满进度待确认、确认、已完成只读、重新打开保留12/12。六配色×明暗像素、键盘Space/Enter和读屏语义通过；实体设备读屏与输入法体验仍需人工验收。

唯一全量失败为`todos_completion_popup_light_1440x900.png`：之前的`8c75ab0`提交已将消息内容改为垂直居中，但该PNG仍是`bfcee74`版本。本轮未修改此消息组件或基线；差异仅为消息内部元素下移4px（1644像素，0.13%），已独立审查并记录。

本机验证日志与截图位于仓库`output/progress-*`，测试服务和模拟器均使用独立数据，完成后已清理。构建目录最后生成的产物均使用正式`lib/main.dart`入口。
