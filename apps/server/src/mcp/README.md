# Codex MCP 接入

知序通过 Streamable HTTP 暴露七模块查询、统计和按连接权限执行的业务写入。MCP 复用 `BusinessModule`，不会调用笔记整理供应商，也不提供应用内聊天或长期记忆。

## 创建连接

升级服务端及客户端后，在知序“设置 → AI 设置 → MCP 连接”创建连接：

- 默认七模块只读；按实际需要勾选写权限，写权限必须同时有读权限。
- 每个连接有独立令牌、有效期及可选 IANA 时区。有效期支持 7/30/90/365 天和“永久”，默认仍为 30 天；永久连接无到期日，可随时撤销，单次准备的固定预览仍限 10 分钟。API 显式传 `ttlDays: null` 表示永久，省略表示默认期限。没有配置时区时，日期操作必须显式提供，例如 `Asia/Shanghai`，服务端不推断设备时区。
- 令牌只在创建成功时显示一次；关闭窗口前复制到宿主使用的环境变量。丢失后撤销并重新创建，列表不能找回明文。
- 撤销立即阻止新的调用及尚未提交的动作；已提交的业务数据和防止离线旧编辑的保护仍然保留。

这是专用静态 Bearer 认证，不使用同步密钥、设备 JWT 或 OAuth 登录。不要把令牌写入仓库、URL、截图或模型提示词。

## 配置 Codex

在运行 Codex 的进程环境中设置 `OMNI_MCP_TOKEN`，然后添加以下 MCP 配置。将地址替换为实际 API 地址：

```toml
[mcp_servers.omni_butler]
url = "https://your-api.example/omni-butler/api/v1/mcp"
bearer_token_env_var = "OMNI_MCP_TOKEN"
tool_timeout_sec = 75
```

本机开发可使用 `http://127.0.0.1:3001/omni-butler/api/v1/mcp`。客户端设置页不会修改用户的 Codex 配置，也不会把一次性令牌永久保存在 Flutter 设置中。

部署时配置 `PUBLIC_BASE_URL` 为对外 API 地址；额外的可信入口使用逗号分隔的 `MCP_ALLOWED_ORIGINS`，例如 `https://your-api.example,http://192.168.1.10:3001`。只接受明确的 HTTP(S) origin，不接受通配符、凭据、查询参数或任意路径。反向代理应保留已配置入口的 Host，且不要记录 Authorization。公网使用 HTTPS。协议为无状态 POST 请求，结果使用 JSON，不要求持久 SSE 连接；GET/DELETE 返回 405。

先让 Codex 调用 `get_capabilities`，核对当前连接实际工具和权限。宿主的工具白名单仍可进一步收紧权限。示例指令：

- “说明知序当前支持哪些功能，以及这个连接能读写哪些模块。”
- “按 Asia/Shanghai 查询本周时间分配，并区分已完成和进行中的估算时长。”
- “获取上月总结的证据包，区分确定数字、部分正文材料和推测。”
- “新增一个物品：书桌，位置是书房。”
- “将这两个物品的位置改为客厅，先列出变更清单让我确认。”

配置字段参考 [Codex 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。传输遵循 [MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)，使用官方 TypeScript SDK。

## 直接写入与批量对话确认

写权限表示允许 Codex 直接操作对应模块数据，不再要求用户到知序批准。现有连接沿用原读写范围。默认仍是只读，写权限必须同时有读权限。

能力版本为 `3.0`，服务器版本为 `3.0.0`。完整权限下公开 65 个工具，实际目录按连接权限筛选；旧单条 `prepare_*` 不再作为公开入口。单条使用业务名称，批量保留固定预览：

1. 宿主为一次逻辑请求生成固定 UUID `requestId`。相同内容的重试必须复用身份，不同内容不能复用；响应不确定时重试原请求，或根据已返回的 `actionId` 调用 `get_action_status`。
2. **单条任务**：目标明确、字段完整时，直接调用 `create_time_entry`、`update_item`、`create_note` 等业务工具。后端自动连续完成真实预演和提交，保留原参数、冲突检查及幂等回执。正常产生的账单、正文版本、子项等关联变化不另算独立目标。
3. **批量任务**：同一用户任务涉及两个及以上独立业务对象时，先调用 `prepare_batch` 固定参数并取得真实预览，再展示目标、数量、变更及关联影响，等待用户在当前对话明确确认后调用 `commit_action`。步骤使用业务工具名（包括 `restore_record`），不得拆分成多个单条调用绕过确认。确认后目标或内容改变须重新确认；数据冲突时停止，不能自动刷新基线覆盖。
4. **取消**：用户取消时调用 `cancel_action(actionId)`，只取消当前连接尚未执行的操作，可重复调用。已提交动作只返回真实回执，不能把取消当成数据回滚。
5. `commit_action` 只执行有效的 `pending` 动作；事务内重查当前连接、模块权限、内部身份及业务基线。连接期限与预览期限分别检查，固定预览最多保留 10 分钟。结果及领域回执同事务保存，响应丢失时查询原 `actionId` 或重试原提交，不能新建请求重复保存。
6. 结果明确区分“服务器已保存、客户端待同步”和笔记“仅保存冲突候选、正式正文未采用”。终态不重新执行；知序设置只读展示完整操作记录及实际结果。

批量确认是 Codex 的对话规则，后端执行授权来自连接写权限；服务端不验证聊天记录，也不接受 `confirmed` 参数作为人工批准证明。初始化 instructions、工具描述和能力说明使用相同规则。已有宿主需重新连接刷新目录与参数；不能按旧清单调用已退役入口。

一次最多 8 个明确步骤、200 个实际变化记录，超限拒绝，不截断影响清单。超过 8 步须先展示完整目标和分批方案，用户确认后逐批准备、提交；跨批不保证原子性，任何一批失败都停止并报告已完成范围。批量不支持依赖预览临时新 ID 的步骤引用。

基线采用相关模块的完整业务事实，包含分类关系和墓碑；同模块无关变化也可能要求重新预览。新建记录的正式 ID 在提交时分配，预览中的临时身份不能作为正式数据。状态完成/回收站等系统生成时刻在正式执行时确定，明确指定的业务时间保持固定。

删除为软删除，恢复保留原身份，必要时恢复同批次子记录，不复活单独删除的旧子记录。没有永久删除、清空回收站或后台清理工具。`undo_action` 仅为成功时间起 10 分钟内、后置基线未变的单条新增准备软删除补偿，再由 `commit_action` 执行；补偿预览不会延长原窗口，提交时再次校验。其他修改使用明确业务动作。会员记录与续费标记不会向供应商真实扣费或退订；事件是周期事务。

原设备 JWT `POST /mcp-management/actions/:id/decision` 返回 410，提示更新客户端和重新连接 Codex；连接管理及操作详情仍使用设备 JWT。

## v3 统一入口和参数

| 入口 | 行为 |
| --- | --- |
| `get_statistics(module, …)` | 统一七模块统计；物品支持省略窗口的全量库存及 `includeAccessories`，其他模块需要窗口 |
| `list_recycle_bin(module, …)` | 统一七模块回收站，分页与模块读权限继续生效 |
| `restore_record(module, id, requestId)` | 直接恢复一条记录，保留各领域同批关联恢复规则 |
| `list_time_entries(status, from?, to?, …)` | `ongoing/finished/all`，默认 `all`；范围成对可选，查询进行中记录可不设窗口 |
| `get_capabilities()` | 返回权限、连接时区、服务器时间、版本和限制；有待办读权限时附带 `todoRecurrence` 调度状态；工具名称、描述和参数以 `tools/list` 为准 |

`from/to` 必须是带偏移的 ISO 时间点，采用左闭右开区间，正范围最长十年。时间列表不再接收 `timeZone/asOf`。统计的 `asOf` 仅用于 time/todos/memberships/events；quotes/notes/inventory 不接收或回显无效截止点。日签、笔记及有购买窗口的物品统计仍使用 `timeZone` 确定自然日边界。全量库存不要求时区。

笔记记录时间统一为 `recordedAt`，例如 `2026-10-22T20:15:30+08:00`；偏移决定记录的日期和日内时钟，后端转换为原存储字段。新增省略取当前时刻，编辑省略保留；不再让模型分别填写 `dayKey/recordTimeSeconds/recordUtcOffsetMinutes`。创建事实仍不可编辑，主动选择沿用 1970 年至当前时刻的限制。

编辑笔记和替换进度步骤时，先取得 `get_note` 或 `get_todo` 返回的 `editToken`，再原样传回对应写工具。令牌绑定读取时的真实基线，不能自造或在冲突后自动刷新；笔记正文候选、标签并发合并和步骤结构检查继续有效。模型不再填写 `expectedRevision/tagsBase/baseline`。新步骤省略 `id`，不传 `null`。

编辑令牌有效期为 24 小时，绑定 owner、连接和对象；它只证明读取基线，不授予写权限。签名使用持久密钥，进程重启后仍可验证，轮换签名密钥后旧令牌失效。使用原 `requestId` 和原参数重试时，先查已有动作再验证编辑令牌，因此过期令牌不影响原动作或成功回执的重放；连接授权、动作期限及终态规则仍须满足。

步骤令牌只签入有序身份与名称的结构摘要，大小不随步骤数增长；准备时在 owner 锁内验证当前结构仍与该摘要一致，才向领域层提供结构基线。顺序或名称变化即冲突，完成状态不计入结构摘要。

会员永久属性对外只用 `billingCycle="permanent"`；后端维护 `isPermanent` 及相关日期规则，避免双重表达冲突。转回周期会员须给有效周期与到期日。会员基础编辑不再接收 `timeZone`，首购和付款仍使用业务时区。待办 `taskType` 只在创建时选择，编辑不能改变任务类型。

## 重复待办后台生成

重复实例由 `TodoRecurrenceService` 在服务启动和每 30 秒后台推进，不再开放要求模型“物化”的工具。列表和统计保持只读，统计仍明确只包含已经生成的实例；停机积压通过持久断点逐轮补齐到今天，不生成未来日期。

调度时区取该 owner 当前有效、具备待办读写权限的 MCP 连接设置。显式时区经 IANA 别名规范化后必须唯一；没有有效写连接、全部未设置时区或存在冲突时区时暂停，并在 `todo_recurrence_states` 记录原因，不猜测服务器或设备时区。有效设置恢复后自动继续。每轮最多 10 个 owner、每个最多 4 个系列、每系列最多 7 天。

断点同时记录锚点、时区及规则变化签名；实际排程变化后从系列锚点重新检查，普通同规则实例不会重置进度。每个系列使用独立保存点，失败只回滚该系列本轮新增和断点，退避 60 秒再试，其他系列仍可提交；失败退避期间不报告为已追平。实例、断点与保护身份在同一 owner 锁事务内保存。

`get_capabilities.todoRecurrence` 对有待办读权限的连接返回 `status/timeZone/reason/checkedAt`，是最近一次调度检查结果，不是实时执行承诺。状态包括 `not_checked`、`idle`、`catching_up`、`blocked_authorization`、`blocked_timezone` 和 `error`；查询状态不触发生成，也不暴露内部系列断点或连接身份。

客户端与后端按规则段的起始日计算周期：连续同规则实例沿用原锚点，规则变化以变更日建立新锚点，单次 `null` 例外不终止系列。从当前及未来关闭主系列须保存 `stopped`，后续普通编辑保留该终止事实；停止系列、永久墓碑及双端稳定身份继续生效。本轮需要更新 Windows 和 Android 的这些逻辑。

第 26 份迁移 `20261022010000_todo_recurrence_worker` 增加私有调度状态与断点；第 27 份 `20261022020000_todo_recurrence_protection` 增加 `todo_recurrence_protections`，持久保护后台实际创建的根任务和子任务，防止旧离线 PATCH/DELETE 覆盖。它不借用 MCP 操作回执，撤销连接或删除记录不移除保护，删除 owner 才级联清理。上述私有表不进入 PowerSync 发布或业务快照。撤权后的调度不会继续写入；物理恢复时仍需撤销旧连接，避免恢复出的授权重新驱动后台任务。

## 时间记录分类

用户指定时间分类时先调用 `list_taxonomies(module="time")`，查询完所有分页，再根据用户名称唯一匹配 `kind="category"` 的条目，将其 `id` 传给四个时间写工具的 `categoryId`。例如“20点到21点40，源哥面试复盘，属于学习”，写入参数使用查询得到的 `categoryId`，预览和实际结果中的 `category` 为“学习”。指定名称重名或找不到时先澄清，不擅自新建、模糊替换或归到“其他”。未指定时遵循下面的新增自动选择规则。

`categoryId: null` 明确清空分类；更新省略保留当前分类。MCP 不再接受兼容 `category` 名称参数。服务端在同一事务校验分类 owner、模块、类型与有效状态，并把规范名称写入现有文本列；分类在准备后改变，提交按已有固定基线返回冲突。展示结果必须依据实际回执。

第24份迁移 `20261021010000_time_category_names` 修复历史 UUID 误写：只匹配同一用户有效的 timeline/category 身份，替换为当前真实名称并更新同步游标，保留记录 ID、时间、活动和备注；不存在、跨用户、其他模块、其他类型、禁用或已删除的分类原样保留。不会猜测未知 UUID 对应的名称。迁移同时作用于可恢复记录；已成功 MCP 历史回执保留原事实，新的查询返回修正后的值。

部署前可只读核对将修复的范围：

```sql
SELECT record.id, record.user_id, record.activity,
       record.category AS old_category, taxonomy.name AS new_category
FROM time_entries AS record
JOIN taxonomy_entries AS taxonomy
  ON record.user_id = taxonomy.user_id
 AND lower(btrim(record.category)) = taxonomy.id::text
WHERE taxonomy.module = 'timeline' AND taxonomy.kind = 'category'
  AND taxonomy.is_enabled = true AND taxonomy.deleted_at IS NULL
  AND record.category IS DISTINCT FROM taxonomy.name;
```

备份后停止旧 API 接收请求，应用迁移，再启动新版 API，并让 Codex 重新连接刷新工具说明。当前文本存储及展示方式兼容已有客户端，此次无需提高同步、本地库或快照版本。离线待上传的旧 UUID 值及无法归属的异常记录仍须核对后通过正常编辑纠正；本迁移只修复执行时服务器已接收的数据。

## 物品、会员分类和待办象限

物品分类、位置和会员分类只接受查询得到的 `categoryIds`/`locationIds`，会员标签使用 `tagIds`；空数组表示清空，更新省略表示保留。MCP 已移除这些分类/位置的文字参数及物品兼容文字 `tags`；历史文字仍可读，笔记 `tags` 仍是规范 UUID 数组。

内部领域兼容接口仍拒绝向物品 category/location/tags 或会员 category 写入 UUID，包括逗号名称列表中混入的 UUID。兼容名称解析只供既有领域调用方，不是 MCP 入参。单独清空分类不影响会员标签、物品位置等其他类型；只改备注不会重写分类。用户指定的分类找不到时先澄清；未指定时遵循下面的新增自动选择规则。

待办 `priorityQuadrant` 完全沿用客户端：`0` 不紧急不重要、`1` 紧急不重要、`2` 重要不紧急（默认）、`3` 重要且紧急。新增、编辑和整树移动均接受 `0` 并拒绝 `4`；工具Schema、字段说明、初始化和能力发现同步采用此口径。旧非法编号不能通过父子继承、未来编辑或重复实例生成继续传播。

第25份迁移 `20261021020000_named_taxonomy_repairs` 仅修复能映射同用户有效分类/位置、且不存在冲突关联的 UUID 文字，同时补齐规范关系、维护下行游标；物品 tags 仅替换可确认的同模块分类/标签 UUID 片段。未知、跨用户、错模块、无效、已有不同关联或普通名称分叉均保留待核对。历史回执保持原执行事实，迁移重复执行不重复建立关联。

已有象限 `4` 不自动映射成其他编号，可先只读查询，再由用户明确指定目标象限后通过正常更新纠正：

```sql
SELECT id, title, priority_quadrant
FROM todo_items
WHERE priority_quadrant NOT BETWEEN 0 AND 3;
```

迁移前同样完整备份并停止旧 API 接收请求，再执行迁移和更新 API，让 Codex 重连；schema12/SQLite26/快照11/wire3不变。已有普通名称与关联分叉需人工核对，不从文字或旧关联任一方推断真实意图。v3 步骤 ID 不再允许 `null`，笔记正文基线通过 `editToken` 传递。

## 新增时自动选择分类或标签

新增时间记录（含开始计时）、物品、会员或笔记时，若用户未指定分类或标签，宿主先查询该模块的 `list_taxonomies` 并读取全部分页，根据内容选择最合适的一个已有项。没有明确合适项时留空，不创建分类或标签，也不强行归到“其他”；查询失败需要报告，不能当作没有匹配。

| 模块 | 自动选择字段 |
| --- | --- |
| 时间 | `categoryId`，选一个 `category` |
| 物品 | `categoryIds`，选一个 `category` |
| 会员 | 优先 `categoryIds`；无合适分类时再用 `tagIds` 选一个标签 |
| 笔记 | `tags`，选一个 `tag` 的 UUID |

每条新增最多自动选择一项。用户明确要求留空、给出空值或已指定分类/标签时，不额外推断；更新已有记录不自动重分类，物品位置也不自动推断。自动匹配有多个同等合适或重名候选时留空；显式指定名称无法唯一匹配时澄清。结果显示实际采用的分类或标签，依据提交回执。

这是宿主的选择规则，后端继续校验传入身份、模块、权限和基线，不新增服务端模型调用。自动分类规则本身不需数据迁移；v3 的后台调度迁移仍需执行。更新 API 后需让 Codex 重新连接。语义选择效果需真实宿主验收，SDK 元数据验证不能替代。

## 总结与来源

`get_review_context` 支持周、月、上一周、上一月和自定义范围，默认周一开始。当前周期只到显式/服务器截止时刻，使用实际 IANA 时区边界；进行中时间记录单列估算，不计未来时长。数字由完整授权范围的后端统计计算，来源明细最多 200 条并声明截断。

笔记材料最多 20 篇、每篇 400 个可见字符，明确提供选中数量、总数及截断标志；需要全文时显式调用 `get_note`。各模块统计各自在一致数据库快照内完成，不宣称跨模块冻结快照，也不把当前事实对过去区间的查询当成历史状态快照。与前期比较同时展示两段范围，基期为零时百分比为 `null`。

来源可通过标准 MCP resource template `omni-butler://records/{module}/{id}` 读取，仍检查当前连接的模块权限；这不是操作系统或 Flutter 深链。正文预览附带 `uri` 和 `fetchTool`，宿主不支持资源时使用详情工具读取。统计引用使用 `get_statistics` 和对应 `module`。总结仅覆盖服务器已接收的正式数据，不含离线设备、本机草稿；材料不足须明确说明。总结文字不自动保存，用户明确要求保存单篇总结时调用 `create_note`，多对象保存仍遵循批量确认。

## 跨端基线保护

同步协议保持 **12**。PowerSync 在本机发生编辑时固化各字段前值，上传时不会从最新本机行重新构造。MCP 回执的 `protectedRecords` 保存实际受影响的业务行，`todo_recurrence_protections` 另外保存后台创建的重复任务根项和子项；两类受保护行的后续旧 PATCH/DELETE 都必须通过字段前值检查，同值重放和独立字段可合并。笔记正文继续使用原修订/候选，标签继续差量合并。PUT 仍只新增，不覆盖现有记录。没有以上保护身份的普通行继续沿用原同步语义，并未改成全库统一修订系统。

若任一步冲突，整笔上传事务回滚，原意图保存在私有 `SyncReceipt.conflict`。客户端不确认原队列，重启及重复上传仍返回同一候选，不能用改写前值绕过已有候选。用户在“设置 → 数据同步 → 同步冲突”核对完整原事务与当前服务器值，可选择稍后处理、采用服务器或明确重新提交本机事务。处理绑定打开预览时的事实摘要；服务器再变化时须重读，不能自动重置基线覆盖。重新提交仍遵守墓碑、领域规则及笔记修订，不能把新增变成更新。原候选保留审计，原设备重试并取得处理回执后才确认队列；此时仍需等待下行。

父记录/分类的删除另外检查当前关联闭包。旧队列没有关联集合基线，因此存在受上述机制保护的子记录、账目、历史、正文版本、日签或标签关联时，即使父项字段未变，也保守转为人工冲突。预览展示原队列之外的当前关联事实并绑定摘要；批准后若又新增关联，旧决策也会被拒绝。只有明确核对这一影响的设备决策才能继续删除，不用父项标量前值假装已经检查了孩子。

另一个窗口是“旧表单仍打开，而 MCP 新值已下行”。六个非笔记编辑表单固定打开时基线，在本机事务内检查后保存，冲突保留草稿和界面，不复制回旧字段；笔记继续使用已有草稿及正文修订保护。会员保存与首购、分类关系也在同一本机事务中。
